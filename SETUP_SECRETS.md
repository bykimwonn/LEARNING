# Setting up the API key (Render) + honest list of what still needs YOU

## 1. How BT LEARNING reads the GROQ key

The app now reads the `GROQ_API_KEY` from **any of these**, in this order:
1. **Environment variable** `GROQ_API_KEY`
2. **Secret file** — Render "secret files". The app looks in:
   - the path in `GROQ_SECRET_FILE` (if you set that), then
   - `/etc/secrets/GROQ_API_KEY`, `/var/secrets/GROQ_API_KEY`, `/run/secrets/GROQ_API_KEY`, `/mnt/secrets/GROQ_API_KEY`
3. A local git-ignored `.env` file (for development only)

So on Render you can use **either**:
- **Easiest:** Environment tab → add `GROQ_API_KEY` = `gsk_...`
- **Or secret files:** Render → your service → **Secrets** section → create a secret file with
  the key, mounted at a path the app checks (or set `GROQ_SECRET_FILE` to its path).

The key is **never hardcoded** and `.gitignore` protects local `.env`.

## 2. To get a free Groq key
1. [console.groq.com](https://console.groq.com) → sign up (no credit card).
2. **API Keys** → **Create API Key** → copy it (starts with `gsk_`).
3. Add it on Render as described above.

## 3. Other env vars you must set on Render
| Key | Value |
|-----|-------|
| `DATABASE_URL` | your Postgres connection string |
| `SECRET_KEY` | a random long string: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `GROQ_API_KEY` | your `gsk_...` key (or secret file) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` / `ADMIN_NAME` | creates the first admin |

## HONEST LIST — what I CANNOT fix, only YOU can do

These are the things that require your account/action in Render/Google/GitHub. They will not work
"fully" until you do them.

1. **Set the GROQ_API_KEY** on Render (env or secret file). Without it, BT AI uses the built-in
   fallback engine (app works, but answers are template-based, not full AI).

2. **Deactivate the old Gemini key** you shared earlier in this chat. It's exposed (you pasted it
   and the repo was public). In Google AI Studio, delete/regenerate it.

3. **Set a strong SECRET_KEY** on Render. Right now it falls back to a known default
   (`bt-learning-demo-secret`), which is a session-security risk in production.

4. **Set DATABASE_URL** (your Postgres). Without it, the app uses SQLite on Render's ephemeral
   disk, so **all data resets on every redeploy**. For launch, you need the Postgres DB.

5. **YouTube playback limitations.** This is the biggest honest one:
   - YouTube **embeds don't load inside the sandboxed preview** here (no network). In your real
     deployed app (a normal browser), they will.
   - Some YouTube videos **block embedding** on external sites. When that happens, the video may
     not play in-app. That's why I added **"Open on YouTube"** buttons — they always work (they
     open YouTube in a new tab).
   - The **white-noise focus sounds** are the reliable in-app audio (they're generated by the
     browser, no YouTube, no internet). Songs/playlists rely on YouTube, which can be blocked or
     limited. **If you want guaranteed in-app song playback, we'd need a YouTube Data API key**
     (free from Google) — you'd have to create that key.
   - The **break auto-switch** opens the break music page when the study timer ends.

6. **Email/SMS notifications** (if we add them later) need an external service key (e.g.
   SendGrid/Twilio) — you'd provide that.

7. **Making the repo private** — your codebase is public right now. Only you can change that in
   GitHub (Settings → change to Private).

8. **Backing up your Postgres data** — Render provides backups; you enable/schedule them.
